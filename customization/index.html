Make it yours

An instance has a handful of knobs, and this page is all of them. What you add to the personas, the one JSON file that describes the instance, the models, the permission rules, the two switches on the Leader's head, and the port. Everything here is yours: an update replaces the payload and leaves every one of these alone.

The personas

A persona is rendered once, when a seat's process starts, from the templates the instance has at that moment, and kept beside that seat's conversation under desks/<Name>/. What you add to it is yours: customization/leader.md or customization/worker.md at the instance root is appended, as it is, to every persona of that kind the instance renders. So an edit changes nothing for a process already running, and reaches every process started after it — the next Worker hired, the Leader after its next restart.

The place for what is true of your workspace and not of the product: the language the team writes in, the shape of a commit message, where a design goes before it is built. Rules the team should hold in front of every turn are better as hard rules, which reach a running session too; a persona addition is read at start and never again.

openovai.json

The instance's description of itself, at the root. The installer writes it — who works here, on which models, on which port, how it signs in; no absolute path, so an instance can be moved and still be itself — and an install over the instance with --force writes any option you give into it. Everything below the first group is optional: absent, the default holds. The server reads the file when it starts, so ovai restart after an edit.

That is the whole list. A key not on it is not read; a value of the wrong shape — a string where a number goes, a pair with three numbers — falls back to the default for that key and nothing else. There is no quiet-hours setting, no log level, no cache. What is fixed in the code instead, and why, is on the defaults page.

Models

The instance was installed with a model for the Leader and one for the Workers, and ovai configuration lists every desk with what it resolves to. A Worker hired with a model beside its name is one that should not run on what the workspace runs its Workers on; that word is kept in desks/<Name>/MODEL, its own file rather than a line of the desk — the desk file is written by its session, and a model kept in there would be a model that session could raise for itself. It goes away with the desk. Leaving the model out at hire writes nothing down, so changing models.worker moves everybody who was never named one, from their next process.

The rules are yours

.claude/settings.json under the instance root is seeded once and then belongs to you: every card you answer with the third button and every rule the Leader settles with permission is written there, and .claude/allowed.md beside it keeps one line per rule — who asked, when, what for. An update touches it for two things and no other: it wires the compound hook into a file that lacks it, and turns Claude Code's commit attribution off in a file that says nothing about it. It adds no rule; it says which of the rules a fresh instance is born with the file has not got, and leaves that to you. A file that says something else about attribution is yours, and an update leaves it. The permissions page has the seeded set and the shape of a rule.

Notifications and theme

Two icon buttons on the Leader's head, beside the theme toggle, are the whole of the notification configuration: an exclamation mark for the action-needed notification (<name> requires your action — a card appeared on some panel) and a bell for the end-of-turn notification (<name> finished their turn — the Leader's turn ended, however it ended). Each is lit while on and slashed across while off, both off to begin with, kept by the browser for that page. The first switch you turn on asks the browser for its permission, the way any site does, and lights only once the browser has granted it; a prompt refused or dismissed leaves the switch off. Nothing is sent while the page is visible — a tab you are looking at tells you itself. A click on a notification brings the page to the front and the panel it came from into view; a burst on one panel replaces its own, never stacks. Sound, and whether anything shows while you are in another app, are the browser's and the system's, not the page's.

At the right edge of the same head, a toggle between light and dark. The page starts light; a choice is kept by the browser for that page, the same way the two switches are.

A fixed port, and the page as an app

--port 0 at install means whatever is free, and ovai start prints the address it actually got. Pick a number when you want the same one every time: a bookmark, or the page installed as a web app. The page ships a manifest and three icons — one of them for a platform that masks icons to its own shape — so the browser's "install" puts it on your desktop like any app, which is what a fixed port is for. The port is on 127.0.0.1 only, whatever the number.
