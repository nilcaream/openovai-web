openovai — the user-level command

One POSIX shell script at ~/.local/share/openovai/openovai, linked as ~/.local/bin/openovai. Read from a pipe — curl -fsSL https://raw.githubusercontent.com/nilcaream/openovai/main/openovai | sh — it installs itself there and says so; if ~/.local/bin is not on PATH it prints the line to add to your shell profile and never edits one. Run from its place it resolves a release, prints it, downloads it once under ~/.local/share/openovai/releases/<version>/ and hands over to that release's installer. It knows one option of its own:

formwhat
openovaithe newest release on GitHub at that moment, printed as openovai 0.16.0 (latest) before anything is done; with no other argument the release's installer asks its questions, and the version question is the only one openovai asks itself, offering latest and the versions already downloaded
openovai 0.16.0 …
openovai --version 0.16.0 …		that release
openovai [version] --root … --user … --leader … --leader-model … --worker-model … --port … --auth …every argument after the version is passed through unchanged to the release's installer; all given, nothing is asked. --force installs over an instance already in place, as an update of it. The options are on the install page

ovai — the instance's command

<root>/bin/ovai, one per instance. Bare ovai prints the help.

commandwhat
ovai helpthe usage; --help and -h the same
ovai statusrunning at <url> (pid, since), or not running; reads runtime.json and then tries the address, so a record a killed server left behind is found out by asking
ovai configurationwhat this instance is: version, who works here, on which models, the port, how it signs in, whether it has a credential (unchecked), when it was installed, every desk with the model it resolves to, where the store is
ovai startstarts the server in the background and prints the whole address, http://127.0.0.1:<port>; a taken port is named with the process holding it; a server already running is reported and left alone
ovai stopparks the room — every session writes its desk and stops, the Leader included, with park.timeout as the deadline — then closes the server; not running is not a failure. kill or kill -HUP of the server's pid reach the same handler
ovai restartstop, then start; prints the new address
ovai plugin <name>writes plugins/<name>.mjs from the scaffold; refuses a name a tool cannot have, a built-in name, and a name whose file is already there
ovai loginunder --auth login, opens a browser once and keeps the credential inside the instance; refuses under inherit and says so
ovai update [--downgrade] [--from <url or directory>]takes the latest GitHub release when it is newer: bin/ and lib/ replaced whole, a file a fresh install would seed and this instance has not got seeded once, everything of yours left alone; refuses while the server or any session of the instance runs, naming the kill line for each; refuses to go backwards without --downgrade
exitwhen
0done
1the server, a plugin or a release said no: the message, and no usage under it
2the command line or the instance: an unknown command, an argument too many, a root that is not an instance; the message with the usage under it
3ovai status: not running

The seeded permission rules

.claude/settings.json, written once at install. Every path rule starts with /, anchored at the instance root. An update adds no rule; it wires the compound hook into a file that lacks it and turns commit attribution off in one that says nothing about it.

listrulewhat
allowmcp__openovaithe tool server: the eleven tools and every plugin
allowRead(/**)reading any file
allowEdit(/reference/**), Edit(/projects/**), Edit(/temp/**)writes under the three trees that are yours; Edit(…) governs every tool that writes a file, Write included — a Write(…) rule matches nothing
allowEdit(/desks/<Leader>/**)the Leader's desk directory; every Worker hired gets the same pair for theirs, withdrawn at retire
allowone Bash(…:*) each for git, mkdir, cd, node, bash, sh, cp, mv, rm, ls, cat, tar, diff, cmp, sha256sum, grep, find, sed, awk, head, tail, wc, echo, chmod, touch, curl, npma seat's ordinary shell commands, matched by the command from its first character — a git -C spelling asks; a cd … && … compound is let through by the hook when every side is allowed and none denied
denyEdit(/desks/*/STATE.md)a desk file is written through write_desk; a stray write is refused without a prompt
denythe instance's own account filesunder .local/
denygit push, sudo, ssha push is yours; a refusal wins over the git rule that would let it through, whatever the hook says

Also seeded: attribution with an empty commit and pr and sessionUrl false, so a commit says what its message says; and the hook lib/hooks/compound.mjs before every Bash call. The instance's Claude Code home turns the built-in memory off.

runtime.log

Every row has the same four columns, single spaces, then the text. No request is ever logged.

columnwhat
momentISO 8601 to the millisecond with the offset of the machine's zone — the clock the page, the desks and the store keep
eventone word, and the event is the level: started, called, tool, failed, queued, wrote, held, released, parked, stopped, plugins, among others
seatthe session the row is about; - for the server itself
idthe tool-use id on called, tool and failed, else -; grep toolu_… runtime.log is a call's whole life, and the three rows name the tool in full, as Claude Code does

The pid, the host, the user and the version are on the started row and on no other. A session's process gone is one stopped row after the last row of its calls, saying what it ended as — stop, restart, idle, park, idle-forced, park-deadline — or, for one that ended on its own, how: exit 1, SIGKILL. The server's own going out is the last row of its run, stopped - - SIGTERM.

The plugin contract

plugins/<name>.mjs; the name is the tool's. Read once, when the server starts.

exportwhat
descriptiona string: what it does and what it refuses; a session reads it before calling
inputSchemaa JSON schema object for the call's arguments
run(args, { seat, role, root, config })the work, sync or async; seat from the secret, role Leader | Worker, root the instance's absolute path, config openovai.json. Answers { text } or { refused }; anything else, or a throw, reaches the caller as a refusal naming the file
not served when
the name is not a letter followed by letters, digits and hyphens, up to 32 in all
the name is one of the eleven the server serves itself
the file does not load
the file loads and lacks one of the three exports

Each is one plugins row in runtime.log naming the file and the reason. The plugins page walks through one.

Requirements

whatfor
a Linux desktoprunning an instance: the page is opened in your browser on 127.0.0.1
sh, curl or wget, tar, sha256sumthe openovai command and the release installer: fetching the release, and the Node.js and Claude Code it pins, and checking them
an Anthropic accountsigning the instance in, with --auth login or a token under --auth inherit

Node.js and Claude Code are not requirements: each release pins the exact versions it was tested with and the installer fetches them under ~/.local/share/openovai/, per user, shared between instances, used by absolute path. Nothing global, no sudo.
