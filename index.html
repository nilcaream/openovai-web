A small team of AI developer sessions, on one machine.

A toolkit for running a small team of AI developer sessions on one machine, built on top of Claude Code. One session is the Leader; the others are named Workers with one task each.

Every session's identity is a directory on disk, not a process — so a session can be replaced at any time without losing the work.

Install it Read the source

The idea

  • A desk is a person. Each Worker owns a directory holding one Markdown state file. That file, not the session's memory, is what a replacement session reads to continue.
  • Handover replaces summarisation. When a session's conversation fills up, it is asked to write its desk and the thread is ended; a fresh one starts on the same desk, in the same panel, and reads the desk first. Nothing is compacted away.
  • One Leader, many Workers. The Leader delegates, takes the Workers' questions and decides what reaches the User. Workers do the work and leave when it ships.
  • Every session is hosted on the page. Nobody has a terminal of their own. The Leader and every Worker get the same panel, with the same text box under it.
  • Built from ordinary Claude Code features. Agent personas, project settings, an MCP server, plus a few shell and Node launchers and a small web page to host them on.

Why a handover, and not a summary

Resuming a conversation the model service has stopped holding costs most of it again at write price: measured at fourteen times an ordinary turn on a conversation of 40,000 tokens, and about twenty on a large one. So a full session is not resumed. It writes its desk, ends, and a fresh one reads the desk and carries on.

This is not a setting and there is nothing to turn on. It is the shape of the thing.

Install

There is no package and no one-line installer yet. You clone the repository and run the installer from it. Every option is required: the installer never prompts and never guesses, so one command line describes a whole instance and can be read back and repeated. 

git clone https://github.com/nilcaream/openovai.git
cd openovai
./install.sh --root ~/trying-it --source . --user Nil --leader Bob \
             --leader-model opus --worker-model opus --port 0 --auth inherit
~/trying-it/bin/ovai start

ovai start starts the server in the background and prints the address it is listening on. Open it, and ask Bob for something on his panel; ovai stop stops it.

What it needs

  • Claude Code
  • Node.js 24 or newer
  • Bash 4
  • tar, to take a newer version
  • A Linux desktop

Where it is

It is a prototype and it says so. The design is being worked out in the open, so the layout, the names and the interfaces will move. The README is the documentation — one read rather than a reference, including the places where what it claims is narrower than it looks.
