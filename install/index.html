Install

One line installs the openovai command. One more creates an instance: a directory of its own, signed in to its own account, served on one port. Node.js and Claude Code are fetched for you, pinned per release. Nothing global, no sudo.

From nothing to a Leader answering

  1. Get the openovai command

    curl -fsSL https://raw.githubusercontent.com/nilcaream/openovai/main/openovai | sh

    It is one shell script. Read from a pipe, it installs itself: a copy under ~/.local/share/openovai/ and a link at ~/.local/bin/openovai, and it says so. If ~/.local/bin is not on your PATH it prints the one line to add to your shell profile and asks you to open a new terminal — it never edits a profile itself. Once per user; every instance after that starts from it.

  2. Create the first instance

    openovai

    With no arguments the release's installer asks its questions: where the instance lives, who it works for, the Leader's name, the models, the port, how it signs in. Before anything else openovai says which version it resolved — openovai 0.16.0 (latest) — downloads that release once, fetches the Node.js and Claude Code it pins, and hands over to its installer. The directory has to be empty or new.

  3. Sign in, and start

    # if the instance signs itself in (--auth login): opens a browser once, the credential stays inside the instance
~/workspace/bin/ovai login
# start the server in the background: it prints http://127.0.0.1:<port> and returns
~/workspace/bin/ovai start

    Open the address it prints. The Leader's panel is in the middle; type what you want and the Leader starts. ovai status says whether the server is running and where, ovai stop stops it.

  4. A second instance, on one line

    openovai --root ~/second --user Ana --leader Max \
         --leader-model opus --worker-model sonnet --port 7800 --auth login
~/second/bin/ovai login
~/second/bin/ovai start

    Every argument after the version is the release installer's own, passed through as it is: give them all and nothing is asked, so one command line describes a whole instance and can be read back, repeated and tested. Two instances on one machine share the runtimes and nothing else — not the account, not the transcripts, not the port. A later instance simply gets the newest release, said out loud; the older one catches up with ovai update.

The options

Each one is the installer's; openovai passes them through and knows only one of its own, the version.

openovai [version]
openovai 0.16.0 … or openovai --version 0.16.0 … takes that release; absent, the newest release on GitHub at that moment, printed before anything is done. Asked interactively, the choice offers latest and the versions already downloaded.
--root
Where the instance lives. It has to be empty or new. With --force an install over an instance already in place is an update of it: the payload is replaced whole and every file of yours is kept.
--user
The person the team works for.
--leader
The name of the session that leads the team.
--leader-model, --worker-model
The models those sessions run on. A Worker can be hired onto another one later.
--port
The port the page listens on, on 127.0.0.1 only. 0 means whatever is free, and ovai start prints the address it actually got; pick a number when you want the same one every time — a bookmark, or the page installed as a web app.
--auth
How the instance gets an account: login or inherit. Below.

What it needs

A Linux desktop. The rest the installer brings: the Node.js and Claude Code an instance runs on are pinned, exactly, per release — chosen and tested when the release is cut — fetched from a fixed address and checked against a checksum, and kept under ~/.local/share/openovai/, per user, outside every instance. Instances on one machine share those runtimes and reuse what is already there; an instance runs them by absolute path and never touches, nor uses, a Node.js or Claude Code the system already has. Nothing lands on your PATH but the openovai command.

Signing in

An instance needs an Anthropic account before it can answer anything. --auth picks how it gets one.

--auth login
The instance signs itself in. A freshly installed one has an empty Claude Code home, so ovai login opens a browser once and the credential is kept inside that instance. Use this when two instances on one machine should be two different accounts.
--auth inherit
The instance takes CLAUDE_CODE_OAUTH_TOKEN from the environment it is started in. Mint that token once on the machine with claude setup-token, export it wherever instances are started from, and every one of them is signed in from its first message, with no browser in the way. The token is long-lived but not forever and cannot refresh itself: when it expires every instance stops at once with the same message, and a new token fixes them all. ovai login refuses under this option and says so.

Either way the instance's Claude Code home is its own, so transcripts and settings stay separate. ovai configuration reports whether the instance has a credential and says plainly that it has not checked it against Anthropic: finding out costs a request, so the first message is where a dead credential shows up. ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN are removed from what an instance runs with, under both options.

From a clone

The same installer, run from the repository instead of a downloaded release:

git clone https://github.com/nilcaream/openovai.git
cd openovai
./install.sh --root ~/workspace --source . --user Ana --leader Max \
             --leader-model opus --worker-model sonnet --port 7799 --auth login

--source is where to install from: a clone, or an unpacked release. The instance copies bin/ and lib/ in, so it never reaches back to where it was installed from.

Taking a newer version

An instance carries its own copy of the toolkit and does not follow it along on its own. ovai update is how it catches up: 

~/workspace/bin/ovai update

It asks GitHub for the latest release, and if that is newer than the version this instance is on it takes it: the payload — bin/ and lib/ — is replaced whole, and a file of yours that a fresh install of this version would have seeded and this instance has not got is seeded once. When the new release pins a newer Node.js or Claude Code, those are fetched beside the ones already there, and an instance still on the older release keeps using the older ones. Desks, conversations, customization/, plugins/, openovai.json, the settings and the Claude Code home are left alone. There is no rollback: taking the release again is the fix.

It refuses while the server is running, and while any session of this instance is running — found on the machine and named with the kill that ends it. It refuses to go backwards by name; --downgrade takes an older release anyway, and --from <url or directory> takes one from somewhere other than GitHub.

A persona is rendered once, when a seat's process starts, from the templates the instance has at that moment. So an update changes nothing for a process already running; every process started after it is rendered from the new templates. What each release changed is in the release notes, written for whoever runs the workspace that takes it.

The ovai command

Each instance has one, at <root>/bin/ovai. With no command it prints the help.

commandwhat
ovai startstarts the server in the background and prints the whole address it is listening on; a port already taken names the process that holds it
ovai statusnot running (exit 3), or running at <url> (pid, since) — found out by asking the address, not by trusting a file
ovai stopparks the room — every session writes its desk and stops, the Leader included, by a deadline — then closes the server; not running is not a failure
ovai restartthe two in a row, and prints the new address
ovai configurationwhat this instance is: version, who works here, on which models, the port, how it signs in, whether it has a credential, every desk with what it runs on, where the store is
ovai loginsigns the instance in, once, under --auth login
ovai plugin <name>writes plugins/<name>.mjs from a scaffold — see plugins
ovai updatetakes the latest release, as above
