Memory and knowledge

A desk is one task and goes away with it. A conversation is shorter still. So an instance keeps one thing that outlives both, and every session reads the same one: the store. It is not a file a session edits — it is reached through two tools and no other way, and a model is asked where a request needs understanding rather than a grep.

Two stores

memory
About the team: hard rules, facts, traps. How this workspace works, what it has decided, what has bitten it before.
knowledge
About the project: facts and traps. What is true of the code, the design, the decisions taken and why.

A record is one of three kinds: a hard rule, a fact or a trap. Every record says who wrote it, when, and — when it replaced one — what it replaced and why. The instance's Claude Code home turns the built-in memory off, so this is the only thing that outlives a conversation, and it is the same for everyone.

recall

recall reads the store, one of three ways: by meaning — "the palette the User prefers", matched by a model, not a grep —, by id, or the whole of a store. It can be narrowed to one kind, and asked to include records whose time has passed, marked. Each record comes as written, with what it replaced — that record's id and text, and the writer's reason. What recall says is the truth: sessions never read the files.

remember

remember writes one record. Nothing is ever deleted or edited in place: a record that changes is superseded by a new one that names it, with who wrote it, when, and the text it replaced, so one file answers "what was here before". The writer says what the record replaces, or says replaces: none for one that is new — the word for "I have read the store and this replaces nothing".

Named neither, a model is asked whether the text restates, widens, narrows or reverses a record already held, and when it does the write is refused, nothing written, naming that record — its id, its text, the model's reason — so the writer answers: by naming it, or by saying none. The store never replaces on its own judgement. A reason goes with every replacement and is refused without one.

A record replaced by mistake comes back with restore: <id>: live again under its own id, as it was — the text, the source, its time limit — while the record that replaced it stands. A restore is not a swap: a text somebody wrote over the lost one is theirs to replace or leave. Writes to one store run one at a time, each reading the files after the one before it has written; the second of two writes that both replace a record is refused, and its writer reads what stands and writes again.

A record can carry an until, absolute; when that passes it leaves what a new session is given, stays visible to recall, and can be renewed. Retiring a record is a write with until: now.

Hard rules

Hard rules are the part of the store every session is given without asking. They are one-liners, numbered, and capped — 25 rules of 200 characters by default, hardRules: { count, length } in openovai.json — and never summarised: a rule over the cap is refused with the cap, the set goes into every new session's instructions verbatim under its set version, and a running session is told the change in front of its next turn. The kind of thing they hold:

Only the Leader writes them; a Worker proposes one to the Leader and is refused if it tries to write it. A rule the User gave carries source: user, renders first, and cannot be replaced by a team write, the Leader included; a User's rule can be scoped to the Leader alone, and then no Worker sees it by any path. A hard rule is not restored the way a fact is — two live rules with one number would be a broken set — it is written again over the rule that holds its number.

The helper

Where a request needs understanding rather than a grep — which records answer a query, whether a new text restates an existing record, what moment "for today" is — the tool asks the helper: Claude Code run once, in print mode and safe mode, with no tools and no MCP server, nothing persisted, from an empty directory outside the instance, on the smaller model at medium effort, with the question as its whole system prompt and the request on stdin. It proposes; the tool checks the answer against what it sent and applies every rule itself. A run that does not answer inside a minute is killed and the call refused, with no retry. It is one request on the account and is held like any other while a usage window is spent.

On disk

The files are markdown with a front matter block, one per record, numbered, under store/memory/ and store/knowledge/; ovai configuration names the directory. A replacement is one more file naming what it replaced; a restore is one more file, a marker naming the record. Nothing edited in place, nothing deleted: the history stays what it was, and one grep over the directory answers what was ever said. Sessions never read them — what recall says is the truth.
