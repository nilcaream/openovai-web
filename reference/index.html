openovai — the user-level command

One POSIX shell script at ~/.local/share/openovai/openovai, linked as ~/.local/bin/openovai. Read from a pipe — curl -fsSL https://raw.githubusercontent.com/nilcaream/openovai/main/openovai | sh — it installs itself there and says so; if ~/.local/bin is not on PATH it prints the line to add to your shell profile and never edits one. Run from its place it resolves a release, prints it, downloads it once under ~/.local/share/openovai/releases/<version>/ and hands over to that release's installer. It knows one option of its own:

formwhat
openovaithe newest release on GitHub at that moment, printed as openovai 0.21.0 (latest) before anything is done; with no other argument the release's installer asks its questions, and the version question is the only one openovai asks itself, offering latest and the versions already downloaded
openovai 0.21.0 …
openovai --version 0.21.0 …		that release
openovai [version] --root … --user … --leader … --leader-model … --worker-model … --port … --auth …every argument after the version is passed through unchanged to the release's installer; all given, nothing is asked. --force installs over an instance already in place, as an update of it. The options are on the install page

ovai update [--downgrade] [--from <url or directory>]takes the latest GitHub release when it is newer: bin/ and lib/ replaced whole, then finished by the version it brought in, with bin/ovai update --finish from the new payload — which fetches the new runtime, takes away what the new version retires, seeds once a file a fresh install would seed and this instance has not got, wires the hooks and turns attribution off — everything of yours left alone. A release is taken only signed: its signature checked against the keys in the instance's own lib/RELEASE_KEYS, its package against SHA256SUMS, and the lib/VERSION inside against the tag, before anything is replaced; a release without them is refused, and GitHub's own archive of a tag is never taken. A rule a fresh instance starts with and this one lacks is not added: the update prints one line, and the server asks for each such rule on the Leader's panel at every start, with what ovai recommends and Ignore (remembered in .claude/ignored-defaults.json). On the version the instance is already on it runs the same finish. Refuses for a session — a process running the code the update replaces — naming the kill line for each, and goes on past anything else a seat left running; refuses to go backwards without --downgrade. --from a directory that is a git checkout takes a build: only on main with nothing git status --porcelain lists, else refused in one line that says which; the instance is then on the first 8 characters of that commit's hash, the version ovai configuration, the page and the server's health show. A build has no order: a release is always taken onto it, another commit always, and the same commit replaces nothing and runs the finish. A directory that is not a checkout, an unpacked release, is taken as a release, with no signature check. Only an http or https address is fetched; anything else is a directory, and one that does not exist, cannot be read or is not a directory is named with the reason. Going back with --downgrade to a version before 0.20.0 says that the hooks in .claude/settings.json name lib/hooks/run.sh, which that version does not have, and must be rewired by hand

The typing hold

A seat waits for you while you type to it. When something arrives for a seat — a Worker's message, a server event — while you are typing in that seat's box, the seat does not start on it straight away: it waits until you send your line or stop typing, so what you were about to say goes in with it instead of landing behind a turn spent on something else.

What is held, and what is not:

  • Only a turn made of Worker messages and server events, and only before it begins. A turn already under way runs on: the server cannot pause a session between its own tool calls.
  • Your own line is never held. Pressing Enter takes whatever is waiting in with it, as one turn, in the order it all arrived.
  • Only the seat whose box you are typing in. Every other seat carries on as before.
  • A keystroke counts, text sitting in the box does not: a box you walked away from with words still in it holds nothing once the quiet has run out.

Two settings, under typing in openovai.json, both in seconds:

keydefaultwhat
typing.quiet10how long after your last keystroke you still count as typing. The page tells the server about a keystroke at most once every two seconds, so the quiet is counted from the last keystroke the server heard, which can be up to two seconds before your real last one. A quiet under two seconds therefore holds only in patches
typing.cap30the longest a waiting turn is held, counted from when it started waiting (the moment it would otherwise have begun), however long you keep typing. Once it goes in and its turn ends, the next thing that arrives while you are still typing can be held again, for a fresh cap

0 in either one turns the hold off. A value that is not a number, or is below 0, is taken as the default. The server reads openovai.json when it starts: a change takes effect at ovai restart.

A timeline with the defaults, on the Leader's panel:

  1. Typing, a message arrives, Enter. You start typing at 14:00:00. At 14:00:04 a Worker's message arrives and the Leader, idle, does not start on it. At 14:00:09 you press Enter: your line and the message go in together as one turn, the message first because it arrived first.
  2. Typing stops without sending. You type from 14:00:00 to 14:00:03 and stop, the words left in the box. At 14:00:04 a Worker's message arrives and is held. Ten seconds after the last keystroke the server heard, at about 14:00:13, it goes in on its own.
  3. Typing past the cap. You type without a pause from 14:00:00. At 14:00:04 a Worker's message arrives and is held. At 14:00:34 the cap is reached and it goes in while you are still typing. When you send your line it reaches that turn the way any line of yours does: at the turn's next tool call, or after the turn if none is left.

runtime.log

Every row has the same four columns, single spaces, then the text. No request is ever logged. Every row is masked as it is written: a key, a token, a password in a URL, an Authorization header, a --token-style flag or a SECRET=-style assignment is written as ***. The rows of every panel are masked the same way, before they are kept.

columnwhat
momentISO 8601 to the millisecond with the offset of the machine's zone — the clock the page and the desks keep
eventone word, and the event is the level. The whole set: started, error, plugins, parking, parked, hired, retired, called, tool, failed, checkpoint, died, closed, queued, wrote, unwritten, self-started, unpaired, interrupt, dropped, redelivered, asked, answered, restart, held, released, quota, untold, stop, stopped, leftovers, usage, unopened. A row with an event outside the set is a mistake in the code and is refused there
seatthe session the row is about; - for the server itself
idthe tool-use id on called, tool and failed, else -; grep toolu_… runtime.log is a call's whole life, and the three rows name the tool in full, as Claude Code does

The pid, the host, the user and the version are on the started row and on no other. A session's process gone is one stopped row after the last row of its calls, saying what it ended as — stop, restart, idle, quota, park, idle-forced, stop-deadline, park-deadline, first-turn-failed — or, for one that ended on its own, how: exit 1, SIGKILL. The server's own going out is the last row of its run, stopped - - SIGTERM.

A day can be read back from the file. hired says a Worker was started on a desk, what it runs on, and whether the desk was new or one it had. retired says a desk was filed away, the model that round ran on, and where the desk went. restart says how full the session that restarted was, in tokens, so "it filled up" is a number rather than a story. quota says which usage window crossed a threshold, the percentage it stood at, when it resets, and the model when the window is one model's own. held says a turn waits, for a quota window or while you type on the seat's panel (the typing hold), and released that it was let go. checkpoint says a Worker reached the number of calls the Leader set. died says the service refused a turn, in the service's own words, and closed that a close reached its deadline with no desk written, and when the desk last was. leftovers says what a seat left running was ended with its session.

Each is one plugins row in runtime.log naming the file and the reason. The plugins page walks through one.

Node.js, npm and Claude Code are not requirements: each release pins the exact versions it was tested with, in lib/RUNTIME, and the installer fetches them under ~/.local/share/openovai/, per user, shared between instances, used by absolute path. This release pins Node.js 24.21.0 and Claude Code 2.1.285. Nothing global, no sudo.
